# Dump format

<link-summary>How every kind of declaration appears in the dump, and how the dump is ordered.</link-summary>

<card-summary>The line-by-line format of api/&lt;package&gt;.api, with an annotated example.</card-summary>

The dump is plain text in Dart-like syntax: declarations and member signatures without bodies. It is meant to be read
by people in a diff, not parsed by tools.

## A complete example

This package:

produces this dump:

```text
// Public API of this package, generated by Inspectra. Do not edit by hand.
// Regenerate it with "dart run build_runner build" or "dart run inspectra api dump".

library package:shapes/shapes.dart

enum Colour {
  red, green;
  final String hex;
}

mixin Logging on Shape {
  void log(String message);
}

extension type Meters(double value) {
  const Meters(double value);
  Meters operator +(Meters other);
}

abstract base class Shape implements Comparable<Shape> {
  final String label;
  Shape(String label);
  factory Shape.unit();
  abstract double get area;
  int get hashCode;
  bool operator ==(Object other);
  int compareTo(Shape other);
  abstract Shape scale(double factor);
  @Deprecated double surface();
}

typedef ShapeCallback = void Function(Shape);

extension ShapeList on List<Shape> {
  double get totalArea;
}

sealed class Unit {}

const String defaultLabel = 'shape';

int shapeCount;

Shape square(double side, {String label = defaultLabel});
```

Note what is not there: `_Square` and `Hidden` (private, and not exported), `Shape.reset` (`@visibleForTesting`), the
enum's constructor (not callable), and every method body.

## Structure

<deflist type="medium">
    <def title="Header">
        Two comment lines, always the same. They tell a reader the file is generated and how to regenerate it.
    </def>
    <def title="library &lt;uri&gt;">
        One section per <tooltip term="public library">public library</tooltip>, in order of the URI. A package with
        <code>lib/shapes.dart</code> and <code>lib/testing.dart</code> has two sections.
    </def>
    <def title="Declarations">
        Every name in the library's <tooltip term="export namespace">export namespace</tooltip>, sorted by name,
        separated by blank lines. Re-exported declarations appear in every library that exports them.
    </def>
    <def title="Members">
        Indented by two spaces inside the declaration's braces. A declaration without public members is written on one
        line with <code>{}</code>.
    </def>
</deflist>

## Declarations

| Kind | Rendered as | Example |
|:--|:--|:--|
| Class | Modifiers, name, type parameters, `extends`, `with`, `implements`, then members | `abstract base class Shape implements Comparable<Shape> { … }` |
| Mixin | `mixin`, `base` when set, `on` and `implements` clauses | `mixin Logging on Shape { … }` |
| Enum | `enum`, then the values on one line, then members | `enum Colour { red, green; … }` |
| Extension | `extension Name on Type` | `extension ShapeList on List<Shape> { … }` |
| Extension type | `extension type Name(Representation)` and `implements` | `extension type Meters(double value) { … }` |
| Typedef | The full alias | `typedef ShapeCallback = void Function(Shape);` |
| Function | The signature | `Shape square(double side, {String label = defaultLabel});` |
| Variable | `const` or `final`, type, name; `const` with its value | `const String defaultLabel = 'shape';` |
| Getter, setter | Explicit accessors | `int get version;`, `set level(int value);` |

Class modifiers are rendered as written: `abstract`, `base`, `interface`, `final`, `sealed`, `mixin class`.

## Members

Members are grouped, and sorted by name within each group:

1. **Enum values**, on one line in declaration order: `red, green;`
2. **Fields**: `static`, `late`, `covariant`, `abstract`, `external`, `const` or `final`, the type and the name. A
   `const` field shows its value.
3. **Constructors**: `external`, `const`, `factory`, then the signature with the class name and its type parameters,
   for example `const factory Shape<T>.empty();`. Primary constructors of extension types are included, so that
   adding or removing `const` shows up.
4. **Getters and setters** declared explicitly. Getters and setters that a field implies are not repeated; the field
   line stands for them, and `final` tells you there is no setter.
5. **Methods and operators**: `external`, `static`, `abstract`, the return type, `operator` for operators, the name,
   type parameters and parameters.

Members inherited from a supertype are not repeated - they belong to the supertype's entry. Members overriding an
inherited one, such as `hashCode` above, are listed, because the class declares them.

### Parameters

Parameters are rendered with their types, names, `required`, and default values:

```text
Shape square(double side, {String label = defaultLabel});
void connect(Uri uri, [Duration timeout = const Duration(seconds: 5)]);
Future<void> send({required String body, Map<String, String>? headers});
```

Changing a default value changes the line, because every caller that omits the argument is affected.

### Markers

| Marker | Meaning |
|:--|:--|
| `@Deprecated` | The declaration is annotated with `@Deprecated` or `@deprecated`. Deprecating something is an API change worth reviewing, and so is removing a deprecated declaration. |
| `abstract` on a member | The member has no implementation: subclasses must provide one. Dart has no keyword for this; the dump adds it so that making a member abstract is visible. |

## Ordering

The dump is fully deterministic:

- Libraries are sorted by URI.
- Declarations are sorted by name, case-sensitively, so names starting with an uppercase letter come first.
- Members are sorted by group, then by name, ignoring leading modifiers and the return type - so changing a return type
  changes a line but never moves it.

Moving a declaration between files under `lib/src`, reordering members in the source, or reformatting the code changes
nothing in the dump.

## What is never in the dump

- Private declarations and members, names starting with `_`.
- Libraries under `lib/src/`, except for what public libraries export from them.
- `part` files, which belong to their library.
- Unnamed extensions: they are visible only in the library that declares them.
- Declarations and members annotated with a non-public annotation - by default `@internal` and `@visibleForTesting`.
- Libraries matching `ignored_libraries`.
- Method bodies, initializers of non-constant variables, comments and documentation.
